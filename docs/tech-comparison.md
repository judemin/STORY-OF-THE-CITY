# Tech Comparison — 렌더링 방식 비교

## 후보

### 1. 순수 Canvas 2D API (현재 선택)
| 항목 | 평가 |
|------|------|
| 픽셀 아트 적합성 | ★★★★★ — `image-rendering: pixelated`, 직접 픽셀 제어 |
| 아이소메트릭 구현 | ★★★★☆ — 직접 구현 필요하나 완전 제어 가능 |
| 애니메이션 제어 | ★★★★★ — `requestAnimationFrame` + `state.running` 직접 제어 |
| 문서/생태계 | ★★★★★ — 표준 Web API |
| 현재 프로젝트 적합성 | ★★★★★ — 의존성 없음, 경량, HiDPI 완전 제어 |

### 2. PixiJS
| 항목 | 평가 |
|------|------|
| 픽셀 아트 적합성 | ★★★★☆ — 지원하나 기본 설정 필요 |
| 아이소메트릭 구현 | ★★★☆☆ — 별도 플러그인 또는 직접 구현 필요 |
| 애니메이션 제어 | ★★★★☆ — Ticker로 제어 가능 |
| 문서/생태계 | ★★★★☆ — 풍부한 문서 |
| 현재 프로젝트 적합성 | ★★★☆☆ — 오버엔지니어링, 번들 추가 필요 |

### 3. Phaser
| 항목 | 평가 |
|------|------|
| 픽셀 아트 적합성 | ★★★☆☆ — 게임 엔진, 설정 복잡 |
| 아이소메트릭 구현 | ★★★☆☆ — 플러그인 존재하나 제약 많음 |
| 애니메이션 제어 | ★★★☆☆ — 엔진 구조에 맞춰야 함 |
| 문서/생태계 | ★★★★☆ — 게임 특화 |
| 현재 프로젝트 적합성 | ★★☆☆☆ — 타이머 앱에 과도한 프레임워크 |

### 4. Three.js (WebGL)
| 항목 | 평가 |
|------|------|
| 픽셀 아트 적합성 | ★★☆☆☆ — 3D 특화, 픽셀 아트에 부적합 |
| 아이소메트릭 구현 | ★★★★☆ — orthographic camera로 자연스러움 |
| 애니메이션 제어 | ★★★★☆ — 제어 가능하나 복잡 |
| 문서/생태계 | ★★★★☆ — 방대 |
| 현재 프로젝트 적합성 | ★★☆☆☆ — 픽셀 아트 감성과 맞지 않음 |

## 추천: 순수 Canvas 2D API

**이유:** 의존성 없이 HiDPI, 픽셀 스무딩 금지, 애니메이션 완전 제어가 가장 직관적으로 가능하다. 아이소메트릭 투영을 직접 구현해야 하지만 이 프로젝트의 핵심 제약(완전 불투명, `state.running` 기반 정지, 960×540 고정)을 다른 프레임워크보다 깔끔하게 만족시킨다.
